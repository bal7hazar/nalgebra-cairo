# Orchestrator handoff

For a new orchestrator session, possibly on another machine. The repository holds everything needed
to continue; the machine-local folders listed below only archive past briefs and reports. A session
hands over to its successor with the Nexus standard (`nexus session orchestrator --handover`); the
live state of the track is `docs/SPLIT.md` §20 and the sections after it, and `docs/PLAN.md` M9.

## Gates

- CI (`.github/workflows/ci.yml`) is the full gate: one `Workspace` job (fmt, parity, generated
  code, lint with and without default features, build), one `library` shard per test package, the
  `Gas snapshot` job (every benchmark against `gas/`, and every test of every package run by exactly
  one shard), `Oracle (golden vectors)`, `Design benchmarks`. Every job is a required status check
  of `main`; add the new shard's check when merging a PR that adds a test package.
- Locally, agents run crate-scoped checks only (the machine is shared and CPU-capped); the
  orchestrator may run `./scripts/check.sh` for a toolchain bump.

## Features (DESIGN D9)

`default` enables everything (parity by default): `statistics`, `blas`, `closures`, `dynamic`,
`sparse` (→ `dynamic`), `io` (→ `sparse`), `macros`, `eigen`, `svd` (→ `eigen`), `qr`,
`cholesky_update`, `full_piv_lu`, `col_piv_qr`, `lblt`, `hessenberg`, `bidiagonal`, `schur`
(→ `hessenberg`), `exp`. A new leaf family gets its own feature in `default`; nothing
ungated may use a gated item (`scarb build -p nalgebra --no-default-features` must pass). Cold
compile of the library: 11.6 GB with the defaults, 6.1 GB without.

## Releases

A release follows `docs/ORCHESTRATOR.md` "Releases": green CI on the release commit, CHANGELOG
dated, `scarb package` verified, the project manager's written go (owner delegation), then
`scripts/release.py --publish` in dependency order and the tag. Versioning: numeric
results are part of the API, so any change of a result is a MINOR bump (pre-1.0); a new `fixed` /
`simba` MINOR means a pull request here to pin it.
