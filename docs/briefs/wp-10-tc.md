# WP 10-TC — nalgebra-cairo toolchain bump: Scarb 2.20.1, starknet-foundry 0.64.0

Lot of the nalgebra track of Slingfall (orchestrator: herdr project `slingfall-nalgebra`), 2026-10-02.
Runs on the VPS as the programme's one heavy suite while it runs (build peak about 11 GB; one heavy build at a time). Branch: the thread's own. Row `TC` of `docs/PLAN.md`.
simba-cairo's own bump (TC-S) runs in parallel; nalgebra consumes the **published** `simba 0.2.0` and
`fixed 0.4.0`, which do not change here.

## 1. Goal, context, files to read first

**Goal.** Move nalgebra-cairo from Scarb 2.19.4 / starknet-foundry 0.61.0 to **Scarb 2.20.1 /
starknet-foundry 0.64.0**, with every gas snapshot, the path proof, the Consumer cost and
`docs/PACKAGES.md` re-measured and every result shown unchanged.

**Context.** Owner's rule D-180 (2026-10-01): every repository migrates to the latest Scarb, libraries
before the game; **no release comes with the bump** (version stays 0.1.1, nothing is published). A
compile drift's minimal case is run on the latest Scarb before any upstream issue. A toolchain bump is
its own PR: nothing else ships in it, except the one documentation note of §2.

**Determinism rules of the programme (slingfall `OPERATIONS.md`, binding):**
- The compiler is not deterministic on several threads: every build whose output is measured, hashed,
  sized or snapshotted runs with `RAYON_NUM_THREADS=1` exported, on 2.19.4 as on 2.20.1.
- The **absolute build path** (not the machine) changes the Sierra bytes, Sierra sha256 and class
  hash of anything holding a closure (closure type names carry the path; grimworld #283). Felt counts,
  CASM, CASM sha256 and **gas are path-free**: gas snapshots may be generated in this worktree or taken
  from CI. `docs/PACKAGES.md` comes from this PR's CI artifact `consumer-cost` (its figures are CI
  timings). Any Sierra sha256 in your report names its machine and absolute build path; a Sierra
  difference between your worktree and CI is expected, not a regression.

Read first: `AGENTS.md` (rules, unit-test placement, definition of done), `docs/ORCHESTRATOR.md`,
`docs/SPLIT.md` §18 and §21-§22 (how Consumer cost and PACKAGES.md are measured; the run-to-run spread
of 0.1.1), `scripts/check.sh`, `scripts/gas_report.py`, `scripts/consumer_cost.py`,
`scripts/packages_table.py` (docstrings), `.github/workflows/ci.yml`, `.github/workflows/split-measure.yml`.

**Learned from simba-cairo's bump (TC-S, simba-cairo #4):**
- Scarb 2.20.1 bundles **Cairo 2.20.0** and refuses `^2.20.1`: `cairo-version` and `assert_macros`
  are `2.20.0` (check the `cairo:` line of `scarb --version`); `snforge_std` is `0.64.0`.
- snforge 0.64.0 lowers the gas of every test by a **constant harness offset** against 0.61.0
  (simba: exactly −7830 on every bench). A uniform offset that leaves every margin over its baseline
  unchanged is the expected shape, not a numeric change: report the offset and the check that no
  entry moved by another amount; report any entry that moves differently individually.
- The host's scarb/snforge shims queue on a shared heavy-build lock: the first build can wait ten
  minutes or more.

## 4. Numeric targets

No optimisation. **Before** = 2.19.4 / 0.61.0 at `origin/main`; **after** = 2.20.1 / 0.64.0. Linux
figures come from CI: before = the last green CI run of `origin/main` (name its id); after = this PR's
CI run.

1. Sierra gas of every snapshot entry (`gas/*.json`): count of changed entries per file, the largest
   moves. **Target: zero change.** A change is not a failure by itself; report the full table.
2. Consumer cost: library lines (must be identical), the marginals and closures before / after against
   the gates (`consumer_cost.toml`), the highest marginal, the facade, the dimension 5-6 closures. State
   which differences exceed the 0.1.1 run-to-run spread (SPLIT §21-§22: svd_eigen6 2.3 s vs 3.5 s,
   facade 29.8 s vs 46.0 s between two runs of the same code).
3. Path proof: pass / fail and any changed path.
4. CI wall time of every job before / after; a job above 15 minutes is reported, not split.
